# PGChecker


## Introduction

The PGChecker is a tool to identify violations against the self-consistent MPI 
performance guidelines using the performance profiles generated by the PGTuneLib library. 
It provides multiple comparators that perform different evaluation of the raw runtime data.

## Installation

`pgchecker` depends on [`pgmpitunelib`](https://github.com/hunsa/pgmpitunelib).

Prerequisites: an MPI library (`mpicc`/`mpicxx` must be in your `PATH`), the GSL library, and CMake (version >= 3.22).

Therefore, the steps to build `pgchecker` are:
1. Build and install `pgmpitunelib`
2. Build `pgchecker` on top of `pgmpitunelib`

Let us assume that we work in the directory `~/tmp/reprobeta`, where we will install everything.

1. Install `pgmpitunelib`
```bash
cd ~/tmp/reprobeta
git clone https://github.com/hunsa/pgmpitunelib.git
cd pgmpitunelib
cmake -DCMAKE_INSTALL_PREFIX=$HOME/tmp/reprobeta/build -B build
cmake --build ./build/ -v
cmake --install ./build/ 
```
Now, `pgmpitunelib` should be installed in `$HOME/tmp/reprobeta/build`.

2. Install `pgchecker`
```bash
cd ~/tmp/reprobeta
git clone https://github.com/hunsa/reprompi.git
cd reprompi
cmake -DENABLE_PGCHECKER=ON -DPGTUNELIB_PATH=$HOME/tmp/reprobeta/build -B build
cmake --build ./build/ -v
```
Now, `pgchecker` is available in `build/bin`.

3. Configure `pgchecker`

All available collectives are part of `pgmpitunelib`, which contains an executable `pgmpi_info` that prints all collectives in CSV format.

We will create a CSV with all these collectives like so:
```bash
$HOME/tmp/reprobeta/build/bin/pgmpi_info > collectives.csv
```
The file should look like this:
```bash
head -5 collectives.csv
cliname;mpiname;algname;rooted
allgather;MPI_Allgather;default;0
allgather;MPI_Allgather;allgather_as_allgatherv;0
allgather;MPI_Allgather;allgather_as_allreduce;0
allgather;MPI_Allgather;allgather_as_alltoall;0
```
You can edit this file, e.g., you can remove lines that should not be tested. Otherwise, the file can just be used as is.
`pgchecker` reads this file from the path given in the environment variable `PGCHECKER_CSV`.
If `PGCHECKER_CSV` is not set, `pgchecker` looks for a file `pgmpi_conf.csv` in the current working directory and aborts if it does not exist.

For example, on a Slurm cluster:
```bash
PGCHECKER_CSV=./collectives.csv srun --mpi=pmi2 -N32 --ntasks-per-node=32 ./build/bin/pgchecker -o ./foo -d -f ./examples/pgcheck/input.txt 
```
or locally with `mpirun`:
```bash
PGCHECKER_CSV=./collectives.csv mpirun -np 4 ./build/bin/pgchecker -o ./foo -d -f ./examples/pgcheck/input.txt
```
The file `input.txt` specifies what to test and how: for each collective, it defines all parameters that `reprompi` should use to run it. So, this file has the format
```bash
collective_name reprompi_parameters
```

For example:
```bash
cat ./examples/pgcheck/input.txt 
MPI_Allreduce --msizes-list=8,80,800,8000,80000 --nrep=5000 --proc-sync=roundtime --rt-bench-time-ms=3000 --rt-barrier-count=0
```



## Running the PGChecker

In the simplest use case, PGChecker is given an input file listing all collective operations to be tested and an output directory (`-o`, required).
The output directory must already exist, unless `-d` is given.

```
PGCHECKER_CSV=./collectives.csv mpirun -np 4 ./build/bin/pgchecker -f input.txt -o ./results -d
```

The input file contains a list of operations to be tested. In each line of the file the collective function to be tested, a (list of) message sizes and the *number of measurement repetitions* for each test are specified, as in the following example.

```
MPI_Bcast       --msizes-list=1024,4096,16384 --nrep=500 --proc-sync=roundtime --rt-bench-time-ms=2000 --rt-barrier-count=0
MPI_Allreduce   --msizes-list=1024,4096,16384 --nrep=500 --proc-sync=roundtime --rt-bench-time-ms=2000 --rt-barrier-count=0
```


## Command-line Options

### Common Options

- `-h` | `--help` print help.
- `-v` | `--verbose` print all evaluations.
- `-f` | `--input=<path>` input file containing the list of benchmarking jobs (tuples of MPI function, message size, number of repetitions).
- `-o` | `--output=<path>` output folder for evaluations and raw data (required). Must exist, unless `-d` is given.
- `-s` | `--csv` additionally write every evaluation table as `.csv` file (next to the `.txt` file).
- `-m` | `--merge` additionally merge the tables of all tested MPI functions into one table per comparer (`results.txt`). For the violation comparers (Violation, DetailedViolation, GroupedViolation), a summary with the number of violations and barrier warnings per collective is written to `stats.txt` and printed.
- `-d` | `--allow-mkdir` create the output folder (including missing parent folders) if it does not exist.
- `-t` | `--test` statistical test used for identification of violations against the performance guidelines. Possible values are: TTest(=0), WilcoxonRankSum(=1), and WilcoxonMannWhitney(=2). Default is WilcoxonMannWhitney.
- `-c` | `--comp-list` a list of comparers separated by `,`. Possible values are: Simple(=0), AbsRuntime(=1), RelRuntime(=2), Violation(=3), DetailedViolation(=4), GroupedViolation(=5), Raw(=6). Default is GroupedViolation.

### Output

For every comparer, `pgchecker` creates a subfolder in the output folder (e.g., `grouped_violation/`, `raw/`)
containing one table per collective (`<collective>.txt`, and `<collective>.csv` with `-s`).
With `-m`, the merged table `results.txt` (and `stats.txt` for the violation comparers) is written to the same subfolder.
The raw measurement data of every algorithm is stored as `data_<collective>_<algorithm>.dat` directly in the output folder.
